# 评分技能的共享约定 · Shared Scoring Conventions

> 本仓多个技能都用加权评分（选品 /100、可行性 1-5 星、联盟可推性六维 /30、联盟客 100 分…）。
> 量表各不相同**没关系**——但**同一份输入跑两次应该得到同一个排名**。本文件定义让评分可复现的最小机械层。
>
> 适用：`amazon-product-selection`、`amazon-product-shortlist`、`affiliate-readiness-audit`、
> `affiliate-program-ops`，以及后续任何加权打分的技能。**新增评分技能请引用本文件，不要另写一套。**

---

## 0. 一句话原则

**算术要确定，锚点要诚实。**
把"怎么算"写死（可复现），把"多少算高分"留成**显式、可按类目校准的默认值**（不假装普适）。

---

## 1. 归一化：原始值 → 维度分

每个维度必须声明**锚点对**（`低分锚` / `高分锚`）和**变换方式**，然后线性插值 + 截断：

```
score = clamp( (f(x) - f(lo)) / (f(hi) - f(lo)) , 0, 1 ) × 满分
```

| 指标类型 | `f` | 例 |
|---|---|---|
| 一般连续量（价格、毛利率、CTR） | 恒等 | 毛利率 15%→0 分锚，35%→满分锚 |
| **重尾/名次型**（BSR、排名、搜索量） | `log` | BSR 用 `log(1/BSR)`；搜索量用 `log(x)` |
| 越小越好（评论数、竞品数、退货率） | 取负或反向锚 | 均评论 5000→0 分锚，200→满分锚 |
| 布尔/枚举（是否有 A+、是否 Prime） | 直接给档 | 有=满分，无=0，部分=半分 |

**规则：**
- 超出锚点范围**一律截断**，不外推——BSR 第 3 名和第 300 名都是满分，差别交给别的维度。
- 反向指标**不要**用 `1 - score` 临时凑，直接把锚点写成反向（低分锚=差值、高分锚=好值），避免符号错。

> ⚠️ **锚点是类目相关的，本仓给的都是"起步默认值"而非普适真理。**
> 「月搜索 >10,000 = 高分」在宠物用品和 3C 完全不是一回事。
> **技能必须在输出里打印本次使用的锚点**，并提示"首次用于新类目时按该类目实际分布校准"。
> 把类目相关的锚点写成通用公式，是用假精度替换诚实模糊——正是本仓要避免的（见 [#16](https://github.com/noique/cross-border-ecommerce-skills/issues/16) 同类问题）。

---

## 2. 缺失值：丢弃 + 重新归一化 + **必须披露**

某维度数据拿不到时：

1. **丢弃该维度**（不要填 0，也不要填"平均分"——两者都会凭空制造排名）。
2. **在剩余维度间按原权重比例重新归一化**，使权重和仍为 1。
3. **强制在输出标注 `本分基于 N/M 维`**，并列出被丢弃的维度。

```
最终分 = Σ(剩余维度 score × 权重) / Σ(剩余维度权重)
```

> 🔴 **这条是本约定里最重要的一条。** 3 个维度打出的 90 分和 5 个维度打出的 90 分，
> 决策含义完全不同。不披露维度数，等于把"数据不全"伪装成"评分很高"。

**熔断：** 若**权重合计缺失 > 40%**，不要输出总分——输出「数据不足，不予评分」+ 缺失清单。
排名的前提是可比，维度都不一样的两个候选没有可比性。

---

## 3. 并列：显式打破，不靠先后顺序

总分相同时，按**本技能已声明的北极星维度**降序打破；仍相同则继续按权重从高到低的维度依次比较；全部相同则**并列同名次**（不要靠文件顺序或模型直觉硬排）。

| 技能 | 并列打破顺序 |
|---|---|
| `amazon-product-selection` | 利润空间 → 竞争度 → 市场需求（利润是已声明的北极星） |
| `affiliate-readiness-audit` | 佣金吸引力 → 转化承接 → 内容可创作性 |
| 其他 | 按该技能权重降序 |

---

## 4. 亮算式：每一维都要能被人工复核

每个维度**至少**输出：`原始值 → 归一化分 → ×权重 → 贡献分`。
可以是表格的一列，也可以是脚注，但**不能只给一个总分**。

```
利润空间：毛利率 31%（锚 15%/35%）→ 0.80 → ×25% → 20.0 分
竞争度  ：TOP10 均评论 1,240（锚 5000/200）→ 0.62 → ×20% → 12.4 分
市场需求：数据缺失 → 丢弃，权重重分配
—— 总分 68.5（基于 4/5 维；缺：市场需求）
```

人能看懂算式，才可能发现锚点定错了。只给总分 = 不可审。

---

## 5. 不要制造超出输入精度的精度

- 输入本身是估算（如工具的"预估月销量"）时，输出分数**保留整数即可**，不要给 `73.48`。
- 分档（如 `≥85 高潜力`）是**决策便利**，不是自然界的门槛——**档位边界 ±3 分内的候选必须标注"接近边界，建议人工复核"**，不要让 84.6 和 85.1 被当成两类东西。
- 评分是**排序工具**，不是真值。技能输出应说明：分数用于**决定看谁**，不是**决定买谁**。

## 6. 自检清单（新增/修改评分技能时逐条过）

- [ ] 每个维度都有明确的锚点对 + 变换方式？
- [ ] 锚点在输出里**打印**了，并提示按类目校准？
- [ ] 缺失值走"丢弃 + 重归一化 + 披露 N/M 维"？
- [ ] 缺失权重 > 40% 时熔断，不给总分？
- [ ] 并列打破顺序**显式**声明了？
- [ ] 每维输出了 `原始值 → 归一化 → 加权贡献`？
- [ ] 档位边界附近标了"接近边界"？
